01
Problem statement

Professionals juggle a constant stream of tasks, blockers, and interruptions throughout the day. Existing scheduling tools require manual calendar management — an activity that is itself a cognitive burden. When priorities shift (a blocker appears, an ad hoc request lands), re-scheduling is time-consuming and often abandoned.

lifeOS removes that friction. Users speak their tasks — raw, unstructured, just like thinking out loud — and lifeOS extracts, schedules, and reschedules them intelligently, with Google Calendar as the live record of truth.

02
Four pillars this POC proves
Voice → task extraction
Whisper transcribes free-form speech. Claude extracts structured tasks with title, estimated duration, deadline, and priority.
Auto-scheduling
lifeOS finds open slots in the user's Google Calendar and creates events, respecting work hours and existing blocks.
Dynamic rescheduling
When a blocker is flagged or an ad hoc task is added, lifeOS automatically cascades and reschedules affected events.
Chain-of-thought clarification
Before acting on ambiguous input, lifeOS surfaces targeted clarifying questions — one at a time, conversationally.

04
Core user stories
User speaks or types a brain dump of tasks
As a user, I want to say "I need to finish the proposal, review Aditya's PR, and prep for the 4pm call" and have lifeOS extract those as discrete tasks, estimate durations, and schedule them into my available calendar slots.
User flags a blocker mid-day
As a user, I want to say "the proposal is blocked on client feedback" and have lifeOS push it out to the next available slot, automatically cascading any affected tasks.
Ad hoc task lands
As a user, I want to say "I need to jump on an urgent call for 30 minutes" and have lifeOS find the best slot for it and tell me what gets pushed as a result.
Ambiguous input
As a user, when I say something vague like "sort out the design stuff", I want lifeOS to ask "what does 'design stuff' refer to, and when does it need to be done?" before scheduling anything.
WhatsApp brain dump (Phase 2)
As a user, I want to send a voice note or text on WhatsApp and have lifeOS process it the same way as the web app, then reply with a confirmation of what was scheduled.
05
System architecture
Frontend Next.js 14 · App Router · Tailwind
Voice recorder component (MediaRecorder API → WAV blob) · Chat thread UI · Task confirmation panel · Calendar preview widget (read-only) · Auth flow (Google OAuth)
API layer Next.js Route Handlers · TypeScript
/api/transcribe → Whisper (OpenAI or self-hosted) · /api/parse → Claude (task extraction + CoT) · /api/schedule → scheduling engine · /api/calendar → Google Calendar proxy · /api/whatsapp → webhook receiver (Phase 2)
AI core Claude claude-sonnet-4-6 · Structured output
System prompt defines the scheduler persona · Conversation history maintains CoT · Returns structured JSON: {tasks[], clarifications[], actions[]} · Streaming for perceived speed
Scheduling engine Pure TS · Stateless
Reads free/busy blocks from Google Calendar · Applies work hours constraint (user-configurable) · Fits tasks into gaps using a greedy first-fit algorithm · Cascade logic for rescheduling: bump shortest-deadline first
Integrations
Google Calendar API v3 (Events: insert, update, delete, freebusy) · Google OAuth 2.0 (nextauth.js) · OpenAI Whisper API (transcription) · Twilio WhatsApp Cloud API (Phase 2)
State / persistence Minimal for POC
Session: NextAuth.js + encrypted JWT · Conversation history: in-memory per session (server) · Task metadata: stored as Google Calendar event extended properties — no separate DB needed for POC

08
Risks + mitigations
High
Whisper latency makes voice feel sluggish — breaks the "speak naturally" UX promise.
Mitigation: stream audio in chunks; show "processing..." with partial transcript. Fallback to Web Speech API for instant transcription with Whisper cleanup.
High
Claude misreads task intent; schedules wrong things → user loses trust immediately.
Mitigation: always show confirmation step before writing to calendar. CoT clarification catches the ambiguous cases before they hit the scheduler.
Med
Google Calendar OAuth token management is complex — refresh failures break the whole app.
Mitigation: use NextAuth.js with automatic token refresh. Surface auth errors clearly with re-auth prompt.
Med
Scheduling engine produces bad slot choices (conflicts, wrong hours).
Mitigation: always show proposed schedule before confirming. Let user drag/edit before commit.
